二、云函数设计（按业务模块合并，action 分发）

// cloudfunctions/post/index.js  —— 一个云函数管帖子的所有操作
exports.main = async (event, context) => {
  const { action } = event
  switch (action) {
    case 'create': return await createPost(event)   // 内含：msgSecCheck 审核 + 写数据库
    case 'list':   return await getPostList(event)  // 分页（每页 20 条，游标分页）
    case 'detail': return await getPostDetail(event)
    case 'delete': return await deletePost(event)
    default: return { code: -1, msg: '未知操作' }
  }
}
云函数action说明
loginlogin / getUserInfocode → openid → 查/建 users 记录
postcreate / list / detail / deletecreate 里先调 msgSecCheck 审核文字+图片，通过才写库
commentcreate / list / delete同样过审；匿名帖的评论也匿名显示
caselist / detail案例库查询（支持关键词搜索）
favoriteadd / remove / list收藏帖/岗位
admindeletePost / deleteComment / handleReport云函数内校验 openid 是否在管理员名单，防止乱删
为什么合并而不是一个操作一个函数：比赛期要频繁部署调试，云函数越少，右键"上传并部署"的次数越少、出错面越小；action 分发在 5 天窗口内完全够用（这是 DeepSeek 方案 A，我认同并采纳）。

六、不建服务器（云开发） vs 建服务器，到底差在哪？

不建服务器 = 微信云开发（你们用的）

类比：拎包入住的服务式公寓——水电、安保、维修全包，你只带行李（写业务代码）。

  • 云函数＝帮你跑代码的"房间"（不用管操作系统）
  • 云数据库＝帮你存数据的"储物柜"（NoSQL，免装 MySQL）
  • 云存储＝帮你放图片/文件的"仓库"
  • 微信登录、内容安全接口＝楼内配套服务，直接调
  • 花费：免费额度够比赛；超出才按量付费
  • 代价：数据在微信云上（平台绑定）、超出额度要钱、特殊算法/重型计算受限

建服务器 = 传统后端（你们不需要）

类比：自己买房装修——什么都自己来，自由但费钱费时。

  • 买/租云服务器（阿里云/腾讯云 ECS，每月几十到几百元）
  • 装操作系统、部署 Node/Python 后端、装 MySQL、写接口
  • 买域名 + ICP 备案 + 配 HTTPS（小程序要求合法域名）
  • 自己管安全、备份、扩容、半夜宕机自己修
  • 自由度高：任何语言、任何算法、任何第三方服务都能接
结论：比赛 + 轻量 + 5 天 → 云开发完胜。等将来要跑复杂算法、要跨平台后端、数据量大到超免费额度，再迁服务器不迟。注意：云开发也是"后端"——"不建服务器"不是"没有后端"，只是把运维交给了微信。
