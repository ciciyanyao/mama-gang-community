B. 三种开发方式对比：原生 vs uni-app vs Taro（谁在"翻译"你的代码）

① 原生小程序（推荐你们用）

你写 WXML / WXSS / JS（微信的"母语"）→ 微信直接运行，没有翻译环节。
产物：只能在微信小程序里跑。

② uni-app

你写 Vue 语法 → uni 编译器翻译 → 可生成微信 / 支付宝 / 抖音小程序 + H5 网页 + App。
代价：要先学会 Vue；多一层编译＝多一层出错点。

③ Taro

你写 React 语法 → Taro 编译器翻译 → 同样可生成多端。
代价：要先学会 React + Taro 的运行时差异；团队无 React 基础时学习成本最高。

对比项原生uni-appTaro
底层架构WXML 渲染层 + JS 逻辑层直接运行，无模拟层Vue 源码编译成小程序代码，运行时再模拟一层 Vue 机制React 源码编译成小程序代码，运行时模拟 React 机制
学习成本学微信自己的语法（HTML/CSS/JS 变体）要懂 Vue要懂 React
构建链无（微信开发者工具直接写）要装 HBuilderX / CLI + npm要装 CLI + npm，配置更重
能跑几个端只微信小程序微信/支付宝/抖音/H5/App/鸿蒙…多端
出问题查哪微信官方文档，资料最全uni-app 社区 + 微信文档Taro 社区 + 微信文档
名词解释："微信一端"＝目标平台只有微信小程序（小程序本来就只能在微信里打开）；H5＝HTML5，即网页版（手机浏览器或微信聊天里点链接打开的网页）；多端＝微信小程序＋支付宝小程序＋抖音小程序＋H5 网页＋安卓/iOS App＋鸿蒙等。"以后迁移 uni-app 不迟"＝比赛 5 天只保微信一个端，不为"将来可能要做别的端"提前选更重的框架；真到那天，用 Vue 重写页面即可，云开发还能继续用。

C. 从开发到上架：四条路，比赛走到第 2 条就够

① 开发版（只在你自己电脑/开发者工具里）→ ② 体验版（上传代码后，把老师、队员的微信号加为"体验成员"，他们扫码就能真机用）＝比赛演示停在这里 → ③ 提交审核（主体资质＋类目＋内容安全）→ ④ 正式发布（所有人可搜到）
环节要求你们要做的
注册账号个人主体免费注册（18 岁以上实名），或企业/个体工商户/政府主体✅ 已完成：个人主体，AppID wx5aa48fa7b914e7ee，云开发 cloud1 已开通（10/4）
体验版上传代码即生成，把成员微信号加为体验成员，扫码可用；不需过审核10/11 前生成体验版给总负责人扫码验收
提交审核社区/论坛类目是"非个人类目"：个人主体做不了；需企业/个体户/政府主体，并提交《非经营性互联网信息服务备案核准》（ICP 备案）等资质；涉及用户发言还须接入内容安全接口比赛阶段不做（体验版演示即可）；正式上架是"以后的事"
正式发布审核通过后公开，可被搜索；后续 UGC 违规会被下架/封禁不追求；答辩时如实表述为"演示原型＋技术验证"
UGC 内容安全的含义：小程序里只要允许用户发帖/评论（UGC＝User Generated Content 用户生成内容），平台就强制要求：① 接入内容安全接口（security.msgSecCheck）自动过滤违规文字和图片；② 有举报和屏蔽机制。即使不上架、只给老师演示，内容也要干净——所以方案里把"msgSecCheck＋举报"列为 P1 必须做。
